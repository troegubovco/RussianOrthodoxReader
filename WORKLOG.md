# WORKLOG

Журнал работ по «Синодалу». Новые записи — сверху.

Что сюда пишется:
- каждый созданный файл с одной строкой о его назначении (отсюда
  `architecture-update` потом поднимает нужное в [ARCHITECTURE.md](ARCHITECTURE.md));
- решения и их причины — особенно те, что не выводятся из кода;
- тупики: что проверено и не сработало, чтобы не возвращаться;
- то, что осталось незакрытым.

Что сюда не пишется: пересказ диффа, косметика, всё, что и так видно в
`git log`.

Формат записи:

```
## YYYY-MM-DD — Короткий заголовок

**Сделано.** …

**Новые файлы.**
- `путь/к/файлу` — назначение в одну строку.

**Решения.** … (и почему)

**Открыто.** …
```

## 2026-07-31 — Распознавание икон: конвейер и экран доведены до рабочего состояния

**Сделано.** Функция распознавания икон по фото собрана целиком и собирается:
офлайн-обучение, экспорт модели, база метаданных, экран съёмки и результата.
Модель — 64.8% top-1 при τ=0.6. Ниже порога вместо ответа показываются
подсказки из индекса прототипов («возможно, это…»). Изменения на момент
записи не закоммичены.

**Новые файлы.**
- `RussianOrthodoxReader/IconRecognition/IconRecognizer.swift` — обёртка над Core ML-классификатором, пороги и разбор результата.
- `RussianOrthodoxReader/IconRecognition/PrototypeIndex.swift` — косинусный поиск по эмбеддингам для сюжетов ниже порога.
- `RussianOrthodoxReader/IconRecognition/IconMetaRepository.swift` — чтение справок о сюжетах из `icon_meta.sqlite`.
- `RussianOrthodoxReader/IconRecognition/IconScanView.swift` — экран съёмки.
- `RussianOrthodoxReader/IconRecognition/IconResultView.swift` — экран результата с альтернативами.
- `RussianOrthodoxReader/ScreenshotMode.swift` — детерминированное состояние для съёмки скриншотов в App Store.
- `Tools/icon_ml/09_scrape_azbyka.py` — сбор описаний сюжетов с Азбуки.
- `Tools/icon_ml/10_build_meta_db.py` — сборка `icon_meta.sqlite`.
- `Tools/icon_ml/11_verify_release.py` — проверка консистентности артефактов перед вкладыванием в бандл.

**Решения.**
- `IconRecognizer.shared` сделан опциональным (`nil`, если артефактов нет в
  бандле), чтобы приложение собиралось и работало без ML-файлов — они
  тяжёлые и не всегда лежат в чекауте.
- Классификатор ограничен iOS (`Vision`/`UIImage`), а `PrototypeIndex` и
  `IconMetaRepository` оставлены кроссплатформенными — macOS-сборка не должна
  ломаться из-за камеры.
- Старые `Resources/Icons/icon_feature_*` удалены: их заменили
  `Resources/IconML/icon_prototypes.f32/.json`, собранные стадией 08.

**Грабли.**
- Скрапер Азбуки требует пина IP — без него сыпется на середине выгрузки.
- MPS-бэкенд при обучении нужно явно гасить в конце, иначе процесс висит на
  выходе.

**Открыто.** Не проверено на «диких» фотографиях — снятых в храме, под углом,
с бликами и в неровном свете. Пороги τ=0.60 / cosine 0.45 подобраны на
чистом валидационном наборе и почти наверняка потребуют правки после полевой
проверки.

## 2026-07-06 — Раздел «Молитвы»

**Сделано.** Добавлена вкладка «Молитвы»: молитвослов и помянник. Собраны
конвейеры выгрузки молитв и баз склонения имён, поднят отдельный
`CKSyncEngine` для пользовательских данных (помянник, закладки) — независимо
от синхронизации позиции чтения. В релиз не выпущено.

**Решения.** Второй sync-движок вместо расширения существующего: у данных
разный жизненный цикл и разная цена конфликта — позицию чтения можно терять,
записи помянника нельзя.

**Открыто.** **Перед релизом развернуть схему CloudKit в Production.**
